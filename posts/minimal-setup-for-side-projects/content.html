The problem with elaborate setups

Side projects die from friction, not from lack of ambition. Every extra tool you bolt on before writing the first line of actual code — a monorepo manager, a custom CLI, a Docker Compose stack — is one more thing that can break on a machine you set up eight months ago and forgot about. The setup below is the one I reach for when I want to be writing code within five minutes.

Editor and formatting

One editor, one formatter, one linter, configured once at the repo root and left alone:

  • A single .editorconfig for indentation and line endings.
  • A formatter set to run on save, not as a separate manual step.
  • A linter with the defaults, only turning off rules that actively fight the codebase's style.

Version control habits

Small, frequent commits on a single branch until the project has more than one contributor. Branching strategies, conventional commit linters, and PR templates are solving a coordination problem that a solo side project doesn't have yet — they can wait until it does.

CI that does just enough

One workflow file, triggered on push, running whatever the project actually needs checked — a test command if there are tests, a build command if there's a build. Nothing speculative. 

on:
  push:
    branches: ["main"]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: ./run-whatever-checks-exist.sh
